# Review of the audit fixes, 2026-09-30

Reviewed `git diff 6108393...5677249`, consisting of the commit `5677249`, “Keep catalog repairs safe across split and hidden records.” Eleven reviewers covered the changed domains and the independent Standards and Spec axes. The original audit and `fix-plan-2026-09-30.md` supplied the requirements. The tree was clean when review started.

Many original triggers are fixed, but the plan's claim that every in-scope finding is now fixed is too strong. Eighteen additional failure cases were reproduced. Some original defects survive in production callers; several new ownership, reading, and interaction paths introduce regressions. The most urgent work is privacy preservation during canonical operations and completing the importer wiring.

All 1,160 committed tests pass, both TypeScript checks pass, and the client/Worker build passes. Those results establish the existing regression coverage, but the additional reproductions exercise cases that coverage misses. No application files or deployments were changed during this review. Temporary tests were removed; this report is the only intended tracked addition.

## Spec

The fix plan targets 39 unique audit findings. It expressly defers 10 others. Review findings below concern the intended fixes or regressions they introduce, rather than reopening that deferred work.

The audit asks matching to “Carry identity fields into matching,” yet real callers do not forward the newly supported binding/language values. It asks bundle imports to “reconcile it when books arrive,” yet linked observations return before the repaired helper runs. Edition Line creation support exists, but production proposal builders omit its input. Cancellation retirement works through the shared helper and PRH path, but Seven Seas clears withdrawal before that helper can act. These are production integration failures, despite successful helper tests.

The scope remains appropriate. Shared title resolution and Worker `waitUntil` declarations support the intended fixes. The outcome claim “Every finding in scope … is now fixed” should be qualified until the cases below pass regression tests. Approval-time withdrawal evidence validation remains a useful safeguard, but this review reports the concrete Seven Seas retirement bypass rather than treating an untested defensive recommendation as another reproduced bug.

## Standards

Two new documented scalability violations remain separate from the functional findings above.

1. **P2: Bound personal repair work and its trail.** `convex/lib/repair/ops.ts:834` reads all entries of a converted box set; the new split helpers read and rewrite all dependent personal rows at `:1192` and `:1223`. `recordMoves` at `:1176` accumulates the trail in one operation stored in one `proposalVersions` document by `convex/lib/repair/audit.ts:104`. Large populations can exceed transaction or document limits. This conflicts with the batching rule at `convex/_generated/ai/guidelines.md:335` and the unbounded-array rule at `:189`. Use bounded stages and separate bounded trail records. This is code-verified and modeled, not a production-limit reproduction.
2. **P3: Count imprints with an aggregate or counter.** The new impact read at `convex/lib/sensitiveOps.ts:1320` collects all child Publishers and filters/counts them. The count-only read conflicts with `convex/_generated/ai/guidelines.md:333`. Its expected importance is small relative to the privacy and importer findings.

No new authored `any`, query wall-clock read, casting-wrapper function, sensitive public registration, or action database access was found in this standards pass. No code-smell heuristic rose above ordinary implementation tradeoffs.

Standards has two findings, led by unbounded personal repair work. Spec has 18 reproduced functional findings, led by privacy widening during canonical operations. These counts are independent review axes.
