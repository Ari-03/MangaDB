# ANN parser audit

Audit date: 2026-09-26. Scope: `convex/ann.ts`, `convex/lib/ann.ts`, and their tests. This audit used read-only public requests and local Convex tests. It did not inspect production records or run an import against production.

## How the import works

The mirror enumerates manga through report 155, fetches details in batches of 50, then builds Series and Volume observations from English GN and eBook release lines. Existing Releases link by ISBN, with a restricted volume-and-format fallback. A separate pass fetches unlinked release pages for publisher and ISBN information, then creates eligible leaf Releases under existing Volumes. Publisher feeds retain higher authority.

Each manga's `<info type="Plot Summary">` comes back in the same batch response. It is decoded, cleaned, and offered as the Series synopsis at weak authority, so it fills a blank and any publisher's text outranks it.

Release pages also carry a `Description:` field: publisher copy that ANN contributors entered. Live pages checked on 2026-10-02 use two layouts. Older pages put the text inline after a `<br>` inside `<p class="easyread-width">`, with `<br>` pairs between paragraphs. Newer pages close that paragraph and put the text in `<div class="simple-html">`, with zero-width spaces after punctuation. Both end at `<p><small>(added on …)</small></p>`. `parseReleasePage` bounds the field by that trailer, so lists, inline `<small>` and bold labels inside the text do not cut it short. The div layout runs to its last `</div>`, and the inline layout to its closing `</p>`. A page with no description, such as release 8116 (June GN 4), carries only ANN's review link in the field: `<b>Description:</b><br><a href="0/0/reviews/new">Submit your own review of this item.</a></p>`. That link is dropped before cleaning. The text then goes through `cleanBlurb` and `cleanAnnDescription`. The second step removes zero-width characters, including entity-encoded ones, and repairs Windows-1252 mojibake that ANN stored ("Tsukasaâ€™s"). A mojibake run is repaired only when it decodes to a Latin letter or punctuation, so real text such as "café…”" stays as it is. The repair runs only for ANN; `cleanBlurb` does not call it. The cleaner also rejects known page chrome, drops ANN's trailing "Notes:" section, and drops the credit tail, since the byline already shows the credits. A credit tail is one or more clauses of the form role, then "by", then names, running to the very end of the text: "Story and art by X.", "Story by X and Art by Y.", "Story and art by X and Original Concept by Y.", "Originally written by X, adapted by Y.". Names must be capitalized words, so prose and lowercase names are kept. Run over the first 1,604 production descriptions, it changed 1,244 and emptied 13 (10 review links, 3 credit-only texts). Six credit endings are left on purpose: three with lowercase names and three with ANN notes after the credit. Every write path uses this cleaner: the page pass, the backfill, the mirror's link, and stored pages offered later. The page state stores it with `descriptionChecked: true`. The text becomes the Release Description at weak authority, on create, on link, and when the mirror later links a line whose stored page holds one. It goes only to a Release with no description and no Human Override on the field. The weekly page pass refetches a linked line's page once when its Release lacks a description and the stored page was never read for one, at most 2,000 times per run, and each action link hands off after 5 minutes. A failed refetch keeps the stored page and records `refetchFailed`. `npx convex run ann:backfillDescriptions '{"limit": 300}'` does the same in bulk at 1 request per second, or for specific pages with `'{"annIds": ["10948"]}'`. It refuses to start while an ANN Import Run is running, unless that run is older than 12 hours and therefore stranded. It stops after five failed fetches in a row, counted across its continuations, logs why it stopped, and skips withdrawn lines.

The 2026-10 production check led to further rules, measured over the 17,414 ANN descriptions and 3,936 raw pre-repair ANN texts in the export:

- A credit is removed only when it opens a sentence, or is the fused "Story and art by" glued to the text before it. The old exemption for two or more glued clauses cut four live pages mid-sentence ("…Based on the series", "Created by Masashi Kishimoto and features"). Dropping it keeps one real glued credit in the raw sample ("…an E.R. physician Story by Koshun Takami and art by Masayuki Taguchi.").
- A credit that is a sentence of its own may also name people in lower case, but only with the lower-case name words seen in the export: ufotable, tartan check, est em, atsushi, great (Oh! great) and und (Girls und Panzer Projekt). No rule separates "tartan check" from "pure accident", so "Created by pure accident." stays. It may also carry ANN's typos ("Sotyr and art by", "Story and and art by", "Written and art by") or a doubled prefix ("Story and art by Written by …"). Prose stays: "…and is created by Atlus.", "- creator of Wild Act.", "and others". A name list ends at a sentence end, except after an initial. 30 texts changed.
- The fused credit opening a text ("Story and art by Taeko Watanabe. Romance between …") is removed: 2 texts.
- "Notes:" about format or reading direction are removed. The page extractor now also ends the Description at ANN's own next field (`<p class="easyread-width"><b>Notes:</b>`) or the "added on" trailer, whichever comes first; a bold-label paragraph inside the copy stays: 5 texts.
- C1 controls ANN serves as code points ("Schneider\u0092s") map to their Windows-1252 characters: 5 texts. Stray entities ("&gt;", the typo "&qout;") are decoded: 2 texts.
- A text that is only retail or listing junk becomes no description: 23 texts. The list covers seller condition notes, shipping terms, Buy.com boilerplate, "Book by NAME" rows, "Language:English.TITLE", a bare genre, ANN's "No further information" placeholder, and three format labels.

Two checks on live pages (2026-10-02). The U+FFFD in "Ber�hren" and "Pok�mon" is in ANN's own data: pages 49313 and 49437 are valid UTF-8 and serve `EF BF BD`, so no refetch fixes them. The page fetch decodes bytes itself all the same, as strict UTF-8 with any invalid sequence read as Windows-1252. Recent VIZ texts that end mid-word ("alarmingly incon") are truncated at ANN: page 52658 ends there, at 882 characters, far below our 4,000-character cap.

Text a past cleaner cut short is gone from storage. `npx convex run ann:listRefreshCandidates '{}'` lists the ANN ids whose Release text ANN wrote and that ends mid-phrase, contains U+FFFD, or contains C1 controls. `npx convex run ann:backfillDescriptions '{"annIds": [...], "refresh": true}'` refetches those pages and replaces the text ANN wrote from each line. A page with no description, or one that would leave less than half the current text, is held unless `"allowClear": true` is passed. A degraded page therefore cannot blank a good blurb. The same guard as the repair applies: no Human Override, no lock, never another source's or a human's text.

Descriptions written before the cleaner changed are fixed by `npx convex run ann:repairDescriptions '{}'`, which makes no network requests. It re-cleans every stored page description and rewrites the snapshot when the text changes. It decides about a linked Release from the Release itself: when the cleaner would change its current description, ANN wrote that text, and this line is the evidence for it, the repair replaces the text or clears it through `reconcileFields`. A Release skipped once, because it was locked or another line wrote its text, is fixed by a later rerun. That write is ANN's own fact, so it adds one approved Proposal, its version, and one Revision citing the release page. A Release with a Human Override, a lock, or text from anyone else is left alone. Each line runs in its own mutation, so a failing line is counted and logged and the walk continues. The repair is safe beside a running backfill and safe to rerun. It returns counts of lines scanned, snapshots fixed, Releases updated, Releases cleared, and errors, and logs them at every hand-off and at the end.

The endpoint choice and batch size match [ANN's API documentation](https://www.animenewsnetwork.com/encyclopedia/api.php). ANN documents a limit of one request per second per IP, a maximum batch size of 50 titles, and source attribution with a link to the relevant Encyclopedia entry. The adapter waits 1.1 seconds before requests and stores those entry URLs. That delay is local to each action; it does not coordinate unrelated processes sharing an IP.

## Reproduced and fixed

1. **Incomplete mirrors withdrew observations.** HTML returned with HTTP 200 looked like an empty report. Missing manga details and malformed report rows also passed silently. Explicit batch failures were collected, but the action still withdrew everything it had not seen and finished successfully. New validation checks the report envelope, item counts, required item fields, detail envelope, and requested detail IDs (the completeness error names the missing manga IDs). A report row without an id or name is skipped and reported rather than aborting the page, and a well-formed but empty first report page fails the run outright. Any reported error prevents withdrawal and finishes the run as failed; the follow-on page pass still chains after such a finished mirror, since it walks unlinked lines on its own and one persistently failing entry must not stop leaf-Release creation. Only an aborted enumeration (invalid or empty report) or a sweep that never received a real detail document (the detail API down) chains nothing, and the latter also blocks withdrawal; the chained pass finishes health-neutral so a failing mirror still reaches the unhealthy alert. Four action regressions reproduced the old behavior before the fix.
2. **Page fetch failures looked healthy.** Forbidden responses and unrecognized HTML were stored on observations but omitted from Import Run errors. Both now fail the page pass after preserving the per-page diagnostic state. Ordinary placement holds, review proposals, and absent pages returning 404 do not count as transport or parsing failures. Two regressions reproduced successful runs with zero errors before this fix.
3. **Fallback release IDs collided.** Lines without ANN release links used only format, volume label, and date. Two different manga and two omnibus ranges could all overwrite the same observation. The fallback now includes the manga ID and complete release text, with ISBN or date as a further discriminator. A four-line regression previously produced one identity and now produces four. Numeric ANN release IDs remain unchanged. Previously stored fallback observations may be withdrawn and replaced on the next complete mirror; this change does not repair historical canonical links created by a collision.
4. **ISBN-10-only pages lost both identifiers.** The page parser discarded a valid ISBN-10 unless the page also supplied ISBN-13. It now derives ISBN-13 from valid ISBN-10. The existing checksum validator still controls acceptance, and conflicting ISBN-10/13 pairs do not retain the inconsistent ISBN-10.

## Remaining work

- Add a small, scheduled read-only canary for report, detail, and release-page parsing. Report counts and required-field coverage separately from successful HTTP requests. Refresh representative fixtures when it detects a change.
- Revisit page freshness. Successful release pages are cached indefinitely and linked lines leave the page candidate query. API release dates refresh, but publisher, ISBN, and price corrections on those pages can remain unseen. Unparsed pages also currently wait 90 days before retrying. A failed pass followed by a no-fetch pass can report success without recovering the original page.
- Validate that a fetched page's manga ID matches the observation before placement. The parser extracts that ID, but placement currently does not use it as a consistency check.
- Reject impossible calendar days such as February 31. Current date parsing only bounds days to 1 through 31. The blanket pre-2010 day-one precision downgrade is an existing heuristic, not a rule documented by the ANN API page reviewed here.
- Review fallback matching around Editions. The release-page sibling search can consider an Edition that covers additional Volumes; it should not attach a single-volume line to an ISBN-less omnibus merely because they share a Volume and format.
- Audit attribution in the public UI. Storing citation URLs establishes available provenance but does not prove that each rendered page meets ANN's attribution requirement.
- Measure production coverage before expanding ingestion. Useful denominators include raw report rows, returned detail IDs, accepted versus rejected release lines, valid ISBNs, publisher resolution, and unplaced observations grouped by reason. No production data was available to this audit, so no production completeness percentage is claimed.
